# Шифрование и btrfs при установке

При автоматическом стирании диска консольный установщик предлагает LUKS2, если
он загружен в режиме UEFI. Пароль вводится дважды и требуется при каждой
загрузке. EFI-раздел остаётся открытым: с него загрузчик читает ядро и initrd.
В итоговом плане установка отмечена как LUKS2.

Пароль проверяется до размонтирования и стирания диска. Он передаётся backend
через анонимный канал, без переменной окружения, аргумента командной строки,
конфигурационного файла или записи в журнале. Для автоматизации используются
`NI_ENCRYPT=1` и открытый дескриптор `NI_LUKS_FD` с номером не меньше 3.
Если `/dev/mapper/cryptroot` уже занят, операция завершается до стирания:
установщик не закрывает чужой контейнер автоматически.

Шифрование доступно для ext4 и btrfs. Автоматическое шифрование в BIOS-режиме
пока не поддерживается. Ручная разметка сохраняет прежний порядок работы.
В проекте используется консольный TUI-установщик; Calamares и графический
установочный образ удалены.

На btrfs создаются подтома `@` для `/`, `@home` для `/home`, `@nix` для `/nix`,
`@log` для `/var/log`, `@snapshots` для `/.snapshots`. Используются сжатие zstd
и noatime. В конфигурации включается `nixithos.snapshots`.

Перед `nixith switch` и `nixith boot` делаются снимки `/` и `/home` только для
чтения. По умолчанию сохраняются последние десять наборов. Параллельные операции
сериализуются блокировкой; при ошибке снимка переключение продолжается
с предупреждением.

Команды: `nixith snapshots list`, `create`, `delete ID...`, `prune`. Параметры:
`nixithos.snapshots.paths`, `.directory`, `.keep`. Каталог назначения должен
существовать на btrfs; имена снимков, полученные из путей, должны различаться.

Это снимки состояния файловой системы. `/nix` и `/var/log` в них не входят;
снимки не удерживают старые замыкания Nix store от сборки мусора и не выполняют
автоматическое восстановление корневого подтома. Для отката программ остаются
поколения Nix, для данных — отдельные резервные копии. Восстановление корневого
подтома требует самостоятельной процедуры из загрузочной среды.

Проверки: `nix-build -A tests.installer-disk` и `nix-build -A tests.snapshots`.
Форма шифрования дополнительно проверяется в PTY: `nix-build -A tests.installer-ui`.
Первая проверяет настоящую разметку в VM и останавливается до установки;
полная установка с ISO и последующая загрузка проверяются отдельным стендом.

На 06.11.2026 разметка прошла за 71,34 с, снимки с переключением — за 30,69 с,
форма шифрования — PASS. Реальная установка LUKS2/btrfs/systemd-boot с dinit
загрузилась после ввода пароля. Переключение установленной системы прошло после
исправления обработки штатно пропущенного ExecCondition; весь набор dinit.units
с новым регрессионным сценарием — PASS. Полные логи — в отдельном VM-стенде.
